Rejeu

Rejouer les versions d'un agent, pas ses logs.

Kiroween 2026 · Frankenstein · le magnétoscope revient, la bobine est l'historique de versions d'un agent.

Le problème, en une phrase

Un agent itère jusqu'à ce que la CI passe, puis l'équipe squash la PR « pour la rendre propre » : les états intermédiaires disparaissent, et l'itération qui a introduit le bug n'existe plus. git bisect ne peut rien (les commits n'existent plus) ; un traceur d'agent ne peut rien non plus (il n'exécute aucun prédicat).

Rejeu capture un checkpoint après chaque appel d'outil mutant, puis rejoue réellement un prédicat sur chaque état, dans un bac à sable, et rend l'index de la version fautive.

Démonstration hors ligne

Données d'une exécution réelle, enregistrée par scripts/make-demo-fixture.mjs : sept checkpoints réels (arbres git), prédicat exécuté pour de vrai à chaque état. La page ne rejoue que le résultat — zéro réseau, zéro exécution, elle ne peut pas échouer devant un jury.

Rapport imprimable A4

Session réelle d'un agent (opencode + broker MCP, 13 nov. 2026) : l'agent a renommé une fonction, cassé deux tests, puis corrigé. Rejeu désigne le checkpoint fautif — rapport de cette session.

Ce que la démonstration ne prétend pas

  • Elle ne mesure rien à l'écran : les temps affichés sont ceux de l'exécution enregistrée, horodatés.
  • Elle ne prouve pas la reproductibilité du modèle : un fournisseur peut changer un modèle sous une version épinglée ; Rejeu le signale au lieu de le masquer.
  • Elle ne remplace pas la revue de code : elle localise la version fautive, pas la qualité du correctif.
