REJEU · rejouer les versions d'un agent, pas ses logs

Un agent casse.
L'équipe squash.
La version fautive disparaît.

Un agent itère jusqu'à ce que la CI passe, puis la PR est écrasée en un seul commit. L'itération qui a introduit la régression n'existe plus.

L'état du dépôt après l'erreur de l'agent


    

      
Le test, exécuté pour de vrai

      
L'historique restant
Un seul commit : l'itération fautive n'a pas de commit.

    

  


  

    
La capture : un checkpoint par état

    

    
Chaque checkpoint est un arbre git (état du dépôt), pas une ligne de log. La chaîne est chaînée : retoucher une entrée la rompt.

    

  


  

    
Le rejeu : le prédicat est exécuté sur chaque état

    

    
Extraction dans un répertoire jetable, réseau coupé, dépôt de travail intact. L'index affiché vient de l'exécution réelle du prédicat.

  


  

    
La timeline

    
    
    
    Checkpoint #0 : l'édition qui casse. Checkpoint #1 : la correction. L'index de la version fautive est #0.
    
  
    

  
    
    
    Un hook qui refuse d'effacer la preuve
    
    
    
    
    Pendant une session capturée, git commit --amend, git reset --hard et git checkout -- . sont refusés : ils invalideraient un checkpoint déjà écrit.
    
  
    

  
    
    
    Le rapport : imprimable, versionnable
    
    
  
    

  
    
    
    Ce que ça donne, mesuré
    
    
    
    
    Banc de 20 sessions : arbres git réels, prédicats réellement exécutés. Les chiffres viennent de docs/MESURES.md.
    
  
    

  
    
    
    Capture non coopérative : l'agent ne sait rien
    
    
    
    
    
    
    Un proxy MCP enveloppe le serveur d'outils de l'agent et capture l'état du dépôt à chaque changement — sans que l'agent ait à coopérer. Trois appels d'outil, deux checkpoints : l'appel de lecture n'en produit aucun.
    
  
    

  
    
    
    Ce que Rejeu ne fait pas
    
    
      
      
    • Il ne prouve pas que le modèle est reproductible.
      • 
      
    • Il ne remplace pas la revue de code.
      • 
      
    • Il ne capture que ce qui passe par le broker ou le proxy : un agent qui n'utilise ni l'un ni l'autre n'est pas capturé.
      • 
      
    • La coupure réseau suppose Linux.
